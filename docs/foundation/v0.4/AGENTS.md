# Agent working contract — Desk v0.4

Applies only in the explicitly adopted Desk handoff/prototype scope. It does not override existing higher-level repository instructions or authorise changes to CoLearni's rebuild. Read HANDOFF.md, START_HERE.md, docs/DECISIONS.md, docs/INTERACTION_CONTRACT.md and the assigned unit first.

## Work discipline

- One assigned, verifiable unit at a time. Do not implement the roadmap wholesale.
- P0 means tooling and pure contract/fixture readiness. P1 requires a new selected reference and explicit assignment.
- No images are included. Previous mockups are retired and not a fallback specification. Produce only one requested screen/state per visual review cycle; do not generate a collage or several alternatives.
- Inspect and preserve existing files and dirty changes. Do not re-scaffold or copy root instructions over an existing repo without approval.
- Use one owner for shared contract/lockfile/navigation/token edits; other agents review instead of competing to write them.
- Keep UI, transport, domain validation, permissions and provider adapters separate. Trusted identity is not a client `actor` field.
- Agents/plugins may not edit learner notes/responses, set read sharing, self-grade mastery, install code, or change security policy.
- Saved note deltas are contextual data, not requests to interrupt/grade. A cheap classifier does not weaken this rule.
- Graph level, node kind, edge type, Bloom target and learner evidence are different fields. Validate level/edge vocabulary and graph cycles; never infer mastery from topology.
- Read docs/NAVIGATION_AND_BRAND.md and docs/MOBILE_INTERACTION.md before shell/editor changes. Keep one navigation definition across viewport/theme states.
- Treat System One outputs as fallible recommendations behind deterministic checks. No model adjudicates authorisation or source-export eligibility.
- Do not invent external APIs. An OpenAI Decisions adapter remains pending verified primary contract and access. Conventional structured outputs are a separately labelled baseline, not that API.
- Hosted providers require explicit configuration/consent. Never silently send local/private data to a remote fallback.
- MCP Apps is a scoped feasibility experiment. Core documents stay native and persistence/permissions stay owned.
- Use synthetic data. No employer source, private papers, secrets, live credentials, public deployments or new services without the assigned authorisation.
- Verify workplace major compatibility and patched versions. Do not force peer conflicts or drift to unspecified latest versions.
- Update PROGRESS.md/NEXT_SESSION.md with actual diffs, commands and limitations. No claims of screenshots, accessibility, security, benchmark wins or product behaviour without corresponding executed evidence.
- Do not stage, commit, amend, push, deploy, buy a domain or adopt a licence without explicit approval. Stop after the unit for review.

## Decision precedence

Explicit founder instructions and accepted constraints > reviewed unit specification > draft contracts/proposed defaults > imagery. Unreviewed imagery has no implementation authority. Licensing intent is not an operative licence; do not add MIT/AGPL/custom terms automatically.
