# User journeys and observable states

These are design scenarios, not claims about implemented features.

## J1 — Start from a broad intention

The learner enters a topic and a desired capability or chooses “help me decide.” Desk proposes a small first activity and a limited source set. A short optional probe establishes a tentative starting point. Show why a prerequisite is useful; let the learner begin without completing a long interview. Failed research yields an honest limitation and a simpler path, not fabricated references.

## J2 — Start from a paper

Upload or reference permitted material → ingestion status → inspect a passage → choose “explain the argument,” “use the method,” “evaluate the evidence,” or a custom outcome. The tutor introduces only the background needed now. Section, figure and equation targets remain traceable. Distinguish full-text access, abstract-only access, parsing uncertainty and retrieved background.

The first Storybook journey uses a synthetic affine-function article. No image or static card represents real parsing.

## J3 — Think in a note

The learner writes with a toolbar or Markdown shortcuts. Save feedback does not move the caret. A note is shared under the disclosed desk setting unless the learner marks it private. The tutor can later use permitted saved passages, but neither saving nor pausing typing starts unsolicited grading. The learner selects “Check my explanation” for explicit adjacent feedback.

Private notes do not appear in the tutor's index, context preview, search snippets or research query. A note reused elsewhere is linked, not silently copied; linking and read-sharing are separate actions.

## J4 — Work through an activity

The task definition stays separate from the answer. The learner predicts a value, explains their reasoning, asks for a hint or views a demonstration. Saved responses retain the task version and assistance. A worked example can be annotated or turned into a new practice variation; it is not relabelled as learner work. “Keep in my notes” preserves a link or an explicitly extracted passage with provenance.

## J5 — Explore with a tool

A reviewed graph/simulation appears as support without moving existing work. Controls have names, ranges, reset and readable alternatives. A parameter change can inform the next tutor turn without automatically triggering one. A stale highlight resolves safely. The learner can pause/dismiss the activity. Unsupported or blocked tools retain fallback text and saved state rather than silently disappearing.

For the MCP variant, trusted host chrome stays outside the iframe. Loading, denied capabilities, unavailable server, invalid state and disconnected app are visible states, not blank frames.

## J6 — Research a gap

The tutor checks the shelf first, then launches a bounded search with a minimal task brief. Results include reason for selection, access status and provenance. New sources land on the shelf; a relevant excerpt may be proposed beside the activity. Research cannot write notes or disclose them in search queries by default. Cancellation preserves already completed learner work.

## J7 — Pause and return

At a meaningful boundary, offer a return point. No forced break, streak penalty or overdue guilt. On return, the learner may attempt a short reconstruction before reading a recap, skip it, or request help. Restore previous work and engine versions without rerunning remote mutations or asking a model to regenerate missing content.

## J8 — Undo without losing writing

Tutor adds a support card → learner writes two paragraphs → learner undoes the tutor addition. Only the relevant addition is reversed. If it contains later learner input or dependencies, show a conflict and preserve the work. Whole-desk restore is a separate, explicitly described recovery action.

## J9 — Take learning elsewhere

The learner exports readable Markdown or a restorable backup. Exports show included items, provenance and unsupported features. Local self-hosters may write into a dedicated host folder; remote users download authorised exports. Public sharing is distinct from a private backup. Import validates paths, sizes, IDs and permissions; it does not automatically install executable engines.

## Journey review

For each scenario, inspect discoverability, reading width, authorship, focus, keyboard path, errors, narrow screens, save recovery and whether the next useful activity is apparent. No evidence of learning is inferred solely from finishing a screen.
