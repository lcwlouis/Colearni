# Incremental work plan

No implementation status is implied. Each unit ends with actual checks, a reviewed diff and an explicit stop. The package itself is not permission to execute every unit.

## P0 limits

Target the workplace major lines; verify supported patched runtime and peer requirements. No broad navigation, branded dashboard, real ingestion, model calls, secure sandbox claim or final editor architecture. Test supplied contracts/fixtures and record limitations. The v0.4 handoff types are a draft vocabulary; runtime validation is a separate task.

## P1 limits

Implement only a reviewed card/note slice. Required states include learner-owned note, adjacent tutor contribution, source attribution, private/shared context disclosure, saving/error/conflict, toolbar keyboard access and blocked agent write. If the editor choice is still open, do not quietly commit a complex framework; use the explicitly reviewed E0 outcome or document a temporary scoped decision.

## X1 limits

X1 is a research spike, not an untrusted public app host. One first-party affine explorer and an unstyled test host suffice. Use the official protocol and a compatible pinned SDK; don't invent custom standard methods. The learning profile is our proposal. No arbitrary generator, marketplace, production credentials or unrestricted remote servers. Native cards remain valid if X1 is rejected.

## Sustainable sequencing

Use spare Claude capacity for independent, well-defined checks, fixtures and small experiments, not speculative feature volume. Do not have multiple agents edit the same contracts concurrently. Assign work ownership and review changed shared files before the next unit.

Ghost's relevant discipline is specification → bounded implementation → end-to-end checks → review/update → next unit. It does not require Ghost's application stack or a later framework rewrite. [R2]

## v0.4 visual and mobile constraints

One screen, theme, viewport and primary state per image request. Do not produce three options in a collage. The last mockups were rejected for regressions and are not a base implementation. Text-only contract work may continue while visuals remain pending. Expanded/collapsed navigation, graph, mobile menu, editing and dark theme are separate later review steps—not permission to render all of them now.

P1/E0 distinguish desktop toolbar and mobile selection-based formatting with accessible fallback. Exact native selection-menu integration must be tested, not assumed. Stable notes/drafts, mobile keyboard and global-drawer/local-tabs behaviour are requirements. Exact destination labels and colour values remain proposed until reviewed.
