# Visual design brief — v0.4, single-view review

## Target

A calm learning desk with sources, learner work and situated tutor help. Persistent objects and a shelf support the intention across sessions. The graph is for connected understanding, not a substitute for the desk.

## Current status

**All earlier generated mockups are retired. No image is included or selected.** This package contains text requirements only. Earlier images mixed brands, navigation, graph semantics, mobile controls and unsupported status claims; do not use them as a baseline or silently reattach them.

## One imagination at a time

For any future visual request, resolve the one screen, one viewport, one theme and one state to show. Record the current invariants, generate only that view, review it, record changes and approval, then wait for the next explicit request. No three-option outputs, multi-screen boards, phone/desktop collages or automatic sequences.

This supersedes the earlier A/B/C visual workflow. Their broad layout ideas may inform reasoning, but there is no instruction to regenerate that comparison or choose an old image.

## Shared constraints before drawing

Read NAVIGATION_AND_BRAND.md, GRAPH_MODEL.md, MOBILE_INTERACTION.md and THEME_BRIEF.md. Keep one global navigation registry, one desk-tab registry and one brand asset. Exact labels, logo and colour tokens remain proposed/unselected until reviewed. Preserve the independent note/tutor/source layers and actual privacy state.

Use `fixtures/paper-session.synthetic.json` as a consistent learning scenario. Equations, plotted outputs and explanations must agree: y=a*x+b, with the example a=2,b=1. No invented sources, copied private research paper, unsupported mastery percentages or claims of fully functioning AI. Synthetic fixtures are design material, not evidence of efficacy.

## Proposed queue — each row is a separate request

1. Main desktop learning desk, expanded navigation, light mode; settle the shell and source/work/support hierarchy.
2. The same desk, collapsed sidebar; no wordmark squeezed into the rail.
3. The same desk, mobile; global menu trigger and bottom desk tabs, not duplicated global destinations.
4. Mobile drawer open; same ordered global destinations as desktop.
5. Mobile selected note text with keyboard/context formatting; no permanent desktop toolbar.
6. Desktop graph with explicit four-level classification and one node family.
7. Mobile graph/list adaptation with the same semantics.
8. One already-approved surface in a revised dark palette inspired by the founder's reference request.
9. Other activity/privacy/history/theme states one by one as needed.

The queue is a recommendation, not authorisation to execute nine images. The founder may choose another first view. Never generate any image merely because the handoff contains a queue.

## Layout/interaction invariants

The learner's writing remains stable while support arrives. A private note is not simultaneously used by the tutor. Help is not a wall of cards. The source stays reachable. Tabs preserve saved and draft work. Authorship, assistance, citation and state are textually identifiable. Undo preserves newer learner work. Dynamic tools stay inside their reviewed host boundaries. Shelf items need not all be expanded.

## Approval and implementation

Record the selected file, exact scope, date, accepted aspects and unresolved defects in VISUAL_SELECTION.md. Approval for one surface is not approval of a brand, other screens or security behaviour. Implement one card/note slice only after that reference and task assignment exist. Browser-based screenshots and interaction tests then verify the implementation; generated images are not pixel-test baselines.
