# Teaching behaviour and learner evidence

## Intended behaviour

The tutor helps the learner work, not merely obtain content. One useful explanation can be short but complete. Avoid compulsory Socratic questioning of novices, endless setup diagnostics, and artificially fragmented explanations. Support changes with the task: orientation, demonstration, partial completion, independent attempt, comparison, critique or creation.

A learner asking for a direct answer receives appropriate help. The interface may offer a smaller hint or a worked example, but does not repeatedly negotiate, shame or lock them out. Record that assistance was available. The product should make good learning easy enough to choose, not make other tools inaccessible.

## Planning loop

Goal + permitted evidence + current work → propose next teaching move → act using bounded tools → observe an attempt or explicit feedback → revise the tentative learner state. No universal fixed “learning style” classification. Preferences, accessibility needs and prior knowledge are separate dimensions.

Bloom tags describe objectives, not a single ordered mastery score. A paper-reproduction goal may involve understanding, applying and analysing in the same session. A psychology critique and a coding exercise can require different representations and evidence.

## Small probes, then ongoing calibration

An optional opening check provides limited evidence. Include “I don't know,” an explanation-first path and learner background input. Prefer tasks relevant to the chosen destination. Do not claim the probe found the exact boundary of understanding.

Use later independent applications and explanations to refine the model. Keep original evidence immutable while derived summaries remain revisable. Never let an old failed attempt permanently dominate newer evidence.

## Evidence record

Record the task/revision, response, stated goal, time, assistance, whether the result was observed or model-inferred, evaluation status, rationale and provenance. Recognition, explanation with hints, independent application, and delayed transfer are distinguishable. A slider movement is an interaction, not a passing assessment. A note may be a quotation or an unfinished thought.

Show learner-facing evidence descriptions such as “Applied with a hint; not checked again yet.” Avoid unsupported percentages, permanently mastered labels, or automatic transfer of understanding across graph links. Permit the learner to correct a summary and keep the correction traceable.

## Breaks and return

Offer a stopping point when the current idea reaches a natural boundary. The learner controls whether to continue. A return check is optional, small and assistance-friendly; it should not turn every session into an exam. Do not optimise for session duration or pressure users with streaks.

## Teaching evaluation set

Include a beginner with no starting point; confident misconception; repeated confusion; direct-answer request; request for an example; correction of the tutor; copied note; partially correct response; private-note temptation; long-absent return; research uncertainty; and an unavailable simulation. Define the appropriate teaching move, not an exact sentence. Human subject reviewers assess correctness and feedback quality before real learning claims.

## Launch evidence

Use observed interface sessions first, then real learning sessions and delayed checks with consent. Track independent performance, perceived control, useful help and return behaviour alongside latency and cost. Small qualitative pilots discover problems but do not establish educational efficacy. Performance with assistance and performance without it are separate outcomes. This document states design commitments, not a claim that Desk is already an effective tutor.
