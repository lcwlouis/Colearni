# Remaining decisions and gates

There is enough shared understanding to export this foundation, compare designs and start P0. More questions should be tied to the next unit, not used as a reason to postpone all work.

| Question | Suggested next action | Status |

## Needed before actual users/private data

Identity/bootstrap and workspace membership; local versus hosted account flows; supported file formats and extraction fidelity; provider/research connections and budgets; retention/deletion/backup policy; reviewed assessment rubric; primary adult pilot audience and concrete material; narrow-screen baseline; security and privacy testing.

## MCP adoption gate

Does one reviewed interactive tool justify the host/broker/isolation complexity? Which exact SDK/protocol versions and capabilities pass? Can state and semantic targets be integrated without vendor-specific leakage? What fallback works for generic apps without the Desk profile? Decide after X1, not from an attractive demo alone.

## Before public release

Final name/domain/trademark review; actual code/contribution/dependency rights; final licence and commercial terms; managed-service price/cost limits; deployment/restore documentation; incident/support handling; accessibility review. School/minor deployments need separate jurisdictional and safeguarding decisions.

## Explicitly later

Live bidirectional Markdown-folder sync, offline-first multi-device editing, simultaneous human collaboration, open plugin marketplace, arbitrary generated compute, universal concept deduplication and sophisticated cross-desk recommendations.

## Facts versus founder choices

The implementation agent should research package compatibility and environment facts rather than ask the founder to supply them. The founder chooses goals, acceptable tradeoffs, visual direction, audience and permissions. A technical default remains labelled proposed until the affected unit is reviewed.

## v0.4 narrowed gates

- **Visuals:** one fresh view at a time; no final mark, palette, graph-node appearance or exact nav registry has been approved. Written consistency/mobile requirements are accepted.
- **Graph:** initial four levels and relation family are grounded in rebuild; extensions/directions/imports require versioned validation, not free-text edge labels. No topology-based mastery.
- **Mobile editor:** test OS selection and app formatting fallback on actual target browsers; determine the editor before promising native custom menu integration.
- **Decision providers:** Jev product and Ollama route have primary evidence; Jev SDK details and OpenAI Decisions primary API/access still need verification. X2 is optional; no primary app milestone is blocked by it.
- **Theme:** requested Singapore school-table inspiration is not an approved national palette. Obtain a concrete reference or state a proposed interpretation in a future single-view review.
